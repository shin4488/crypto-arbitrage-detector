# Crypto Arbitrage Detector

Binance と OKX の板を突き合わせて、手数料を引いても利益が残る裁定（アービトラージ）の機会を見つけて表示するツールです。注文は出しません。表示するだけです。

- バックエンド: Go。取引所との WebSocket 接続、検知、画面への配信を担当します
- フロントエンド: React + TypeScript（Vite）。ビルドした画面は Go のバイナリに埋め込むので、動かすコンテナは1つで済みます

## 画面の見方

上から順に、大事なものほど上に並んでいます。文章ではなく数字とラベルで読めるようにしています。

1. **接続の状態（右上）**: 「Binance・OKXに接続中」なら正常です。サーバーや取引所との接続が切れると、その名前と「再接続中…」が出ます
2. **利益が出る取引（あるときだけ）**: 「BTC/USDT　OKXで買い → Binanceで売り　+1.23 USDT」のように、ペア・方向・利益を緑の帯で並べます。無いときは何も出ません（各ペアの「利益なし」で分かります）
3. **通貨ペアごとの枠**
   - 右上に「利益あり」「利益なし」「データ待ち」のどれかが出ます
   - より有利な方向（利益が出るならその方向）と、取引金額ぶんの式 **価格差 − 手数料 ＝ 差引** を数字で並べます。差引がプラスなら利益、マイナスなら赤字で、その大きさが利益までの距離です
   - 板で利益が出る量が取引金額に足りないときは、その量で計算してその旨を添えます
   - 各取引所の買値（ask）・売値（bid）と、最後に更新されてからの経過時間。有利な方向で使う「買う取引所の買値」と「売る取引所の売値」には色と「買」「売」の札が付くので、いくらで買っていくらで売るかが一目で分かります
4. **検知履歴**: 利益が出ていた期間を1件として、時刻・取引・最大純利益・継続時間を並べます

カードの右上の「↑ ↓」で並び順を変えられ、「−」で折りたたむと見出し（ペア名と利益あり／なし）だけになります。見たいペアを上に置き、見ないペアは畳んでおく、という使い方ができます。並び順と折りたたみはブラウザに保存されます。

カードのすぐ上の「取引金額」で、いくらぶん売買するかを指定できます（既定 100 USDT。金額 ÷ 買値 で数量にし、式も履歴もその数量で計算します）。値が変わった箇所は一瞬背景が光ります。表示言語（日本語 / English）も右上で切り替えられ、言語はブラウザに保存されます。画面の最後の手数料の注記にある ⓘ を押すと、手数料の根拠と各取引所の公式手数料ページへのリンクが出ます。利益が出ている間はタブのタイトルに `● BTC +1.23` のような目印が付くので、ほかのタブを見ていても気づけます。

## 動かし方

### 本番相当（Docker）

```bash
docker compose up --build
```

http://localhost:8080 を開きます。設定を変えたいときは `backend/config.example.json` をコピーして `config.json` を作り、`docker-compose.yml` の `ARB_CONFIG` と `volumes` のコメントを外してください。

### 開発

Go も Node.js もローカルに入れずに済むように、開発用の構成も Docker で動かします。

```bash
make dev
```

画面は http://localhost:3000、バックエンドは 8080 で動きます。どちらもソースを変更すると自動で反映されます（フロントエンドは Vite が数秒で差し替え、バックエンドは `backend/scripts/dev.sh` が `.go` の変更を検知して再起動します）。

本番相当の `docker compose up`（8080）はビルド済みの画面を配信するので、変更は反映されません。開発中は `make dev` の 3000 番を見てください。

テストと静的検査:

```bash
make test   # バックエンド（Docker 内の Go）とフロントエンドのテスト
make lint
```

細かいタスクは `backend/Makefile`（`make help` で一覧）と `frontend/package.json` の scripts にあります。ローカルに Go がある場合は `make test GO=go` のように切り替えられます。

## 検知のしくみ

### 対象

- 取引所: Binance（Partial Book Depth、20段・100ms）と OKX（books5 チャネル、5段・変化があったとき100ms）
- 通貨ペア: BTC/USDT、ETH/USDT、XRP/USDT、SHIB/USDT、DOGE/USDT。設定で増やせます

### 利益の計算

「買い元の ask を取って買い、売り先の bid を取って売る」前提（どちらも taker）で計算します。

- 1単位あたりの手数料込みの損益 = `bid × (1 − 売り側の手数料率) − ask × (1 + 買い側の手数料率)`
- これがプラスである限り、買い元の ask と売り先の bid を上の段から順に突き合わせて数量を積み上げます（2本のポインタで走査するので、計算量は段数に比例します）
- 純利益 = 売りの受取代金 − 買いの約定代金 − 両方の手数料
- 数量に固定の上限や下限はありません。受け取った板の段数が事実上の上限で、板を使い切ったときは「実際の機会はこれより大きいかもしれない」と表示します
- 手数料は損益を USDT にそろえるため、買いは約定代金に上乗せ、売りは受取代金から差し引く形で扱います。手数料率は取引所ごとに `takerFeeRate` で設定できます（既定 0.1%）

同じ取引所では bid < ask なので、両方向が同時に利益になることはありません。

### 機会（履歴の1件）とは

ある通貨ペア・方向で、手数料込みの純利益がプラスになった時点から、プラスでなくなった時点（または取引所の切断）までを1件として数えます。継続中は最大純利益と、そのときの数量・平均価格を更新します。履歴はメモリに最新 `history.limit` 件（既定 200）だけ持ち、サーバーを再起動すると消えます。

### データの鮮度

「n 秒より古いデータは使わない」といった時間の閾値はありません。板が更新される頻度は相場次第で（OKX は変化があったときしか送ってきません）、時間では新鮮さを判断できないからです。代わりに、取引所との接続が切れたらその取引所の板をすべて捨て、つなぎ直して新しい板が届くまで評価しません。各板の最終更新からの経過時間は画面に出しています。接続の生存は WebSocket の ping/pong と受信タイムアウトで見張り、切れたら間隔を広げながら再接続します。

### 注意

- 表示する利益は板のスナップショットから計算した理論値です。実際には、注文が届くまでの板の変化、取引所間の資金移動、最小注文数量や刻み、手数料ティアの違いなどで結果が変わります
- このツールは投資の助言ではありません。注文も出しません

## 設定

設定は「コードの既定値 → JSON ファイル → 環境変数」の順に上書きされます。JSON に知らないキーがあるとエラーにします（タイプミスに気づけるように）。

| キー | 既定値 | 説明 |
| --- | --- | --- |
| `server.addr` | `":8080"` | 待ち受けアドレス |
| `server.allowedOrigins` | `[]` | WebSocket 接続を許可する追加の Origin。同一オリジンは常に許可 |
| `exchanges[].id` | `binance`, `okx` | 取引所 ID（`backend/internal/exchange/registry` に登録されているもの） |
| `exchanges[].name` | 取引所ごとの既定名 | 表示名 |
| `exchanges[].takerFeeRate` | `"0.001"` | taker 手数料率（0.001 = 0.1%） |
| `exchanges[].wsUrl` | 取引所ごとの既定 URL | 接続先の上書き。テストやプロキシ用 |
| `pairs` | BTC, ETH, XRP, SHIB, DOGE の各 /USDT | 通貨ペア（`BASE/QUOTE` 形式） |
| `history.limit` | `200` | 保持する履歴の件数 |
| `log.level` | `"info"` | `debug` / `info` / `warn` / `error` |
| `log.format` | `"text"` | `text` / `json` |

環境変数: `ARB_CONFIG`（設定ファイルのパス）、`ARB_ADDR`、`ARB_LOG_LEVEL`、`ARB_LOG_FORMAT`

取引所の API キーのような機密情報は使いません（公開のマーケットデータだけを読んでいます）。将来必要になっても環境変数で渡し、リポジトリには入れません。

### 通貨ペア・取引所を増やす

- 通貨ペア: 設定の `pairs` に `"SOL/USDT"` のように書き足すだけです。取引所ごとのシンボル表記（`SOLUSDT`、`SOL-USDT`）は自動で組み立てます
- 取引所: `backend/internal/exchange/` に `exchange.Feed` を実装したパッケージを作り、`registry` に登録します。検知エンジンは取引所の全組み合わせを評価するので、3つ以上でも動きます

## 構成

```
Binance WS ─┐                                  ┌─ ブラウザ
            ├─► exchange feeds ─► engine ─► server (hub) ─┤
OKX WS ─────┘     板の受信       評価・履歴   WebSocket 配信  └─ ブラウザ
```

```
backend/
  cmd/server/            エントリポイント（設定の読み込み、シグナル処理、ヘルスチェック）
  internal/
    domain/              通貨ペア・板などの基本の型
    arbitrage/           板を突き合わせて裁定を評価する純粋関数
    engine/              板の保持、両方向の評価、機会の履歴、接続状態
    exchange/            フィード共通のインターフェースと、再接続付き WebSocket クライアント
      binance/ okx/      取引所ごとの購読と解析
      registry/          取引所 ID から実装を引く
    server/              ブラウザ向け WebSocket 配信（クライアントごとに最新の状態だけ送る）
    wire/                配信する JSON の形式
    config/              設定の読み込みと検証
    webui/               ビルド済みフロントエンドの埋め込み配信
    app/                 各部品の組み立て
frontend/
  src/
    protocol/            サーバーから届くメッセージの型と検証
    state/               届いたメッセージを画面用の状態に反映する reducer
    ws/                  自動再接続付き WebSocket クライアント
    hooks/               受信・タブ通知・設定の保存などのフック
    components/          画面の部品
    i18n/                日本語 / 英語の文言（初回はブラウザの言語設定、以後は画面で切り替え）
    format/              10進文字列の表示整形
```

### 配信の形式（サーバー → ブラウザ、`/ws`）

つないだ直後に `init`（取引所、全ペアの評価、履歴）を1回送り、その後は変化があったものだけを送ります。金額と数量は文字列、時刻は UTC の ISO 8601 です。

| `type` | 内容 |
| --- | --- |
| `init` | `exchanges`, `pairs`, `history`, `seq` |
| `pair` | 通貨ペア1つ分の最新の評価結果 |
| `episode` | 機会の開始・最大値の更新・終了 |
| `exchange` | 取引所の接続状態の変化 |

`seq` はサーバー全体で単調に増える通し番号です。`init` より前のイベントを受信側が捨てるために使います。配信側はクライアントごとに「対象ごとの最新メッセージ」だけを持つので、読み出しの遅いクライアントがいても待ち行列が伸びず、ほかのクライアントにも影響しません。

エンドポイント: `/`（画面）、`/ws`（配信）、`/healthz`（生存確認と取引所の接続状態）

## 開発の方針

- テストは仕様を説明する名前を付け、仕様を変えるときはまずテストを変えてから実装します
- CI（GitHub Actions）では、フォーマット・vet・race テスト・golangci-lint・govulncheck・型検査・Biome・ビルド・Docker イメージの起動確認・秘密情報の混入検査（gitleaks）を回します

### サプライチェーン対策

- Go の依存は `gorilla/websocket` と `shopspring/decimal` の2つだけ（どちらも推移的依存なし）。`go.sum` と Go のチェックサム DB で検証します
- フロントエンドの実行時依存は `react` と `react-dom` だけ。lint とフォーマットは単一パッケージの Biome、TSX の変換は Vite 内蔵の機能を使い、Babel 系のプラグインは入れていません
- Yarn（Berry）の設定で、依存のインストール時スクリプトを禁止し（`enableScripts: false`）、公開から7日経っていないバージョンは取り込みません（`npmMinimalAgeGate`）。バージョンは完全に固定します
- Docker のベースイメージは digest で固定、実行イメージは distroless（シェルなし、非 root）。GitHub Actions はコミット SHA で固定します
- Dependabot は7日のクールダウンを置いてから更新を提案します
